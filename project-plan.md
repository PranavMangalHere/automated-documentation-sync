# Agentic SDLC Pipeline — Project Plan

## Project: Automated Documentation Sync

A **GitHub Copilot-native agentic pipeline** that accepts any Python project user story and drives it through the full SDLC — from requirements to a merged PR — using **GitHub Copilot Custom Agents, Skills, Instructions, Prompts, and Hooks**. You interact primarily with the orchestrator; it manages all specialist agents internally.

---

## Interaction Model

| Level                 | Agents                                                                           | Behavior                                                                                  |
| --------------------- | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| L1 — Deep Interactive | Requirements, Architecture                                                       | Agent asks clarifying questions; you answer; it iterates until you approve                |
| L2 — Run + Approve    | Design Review, Impl Planner, Implementation, Doc Sync, Code Review, Verification | Agent runs autonomously, shows output, orchestrator waits for your "y/n" before next step |
| L3 — Explicit Approve | PR                                                                               | Orchestrator shows full PR draft; only creates PR after your explicit confirmation        |

**Entry point**: `@orchestrator process user-stories/user-story-1.md`

**You never invoke subagents directly.**

---

## Pipeline Flow

```text
user-stories/user-story-N.md
        │
        ▼
[ORCHESTRATOR AGENT]
        │
        ├─[L1]─► Requirements Agent ──► docs/requirements.md
        │
        ├─[L1]─► Architecture Agent ──► docs/architecture.md
        │
        ├─[L2]─► Design Review Agent ──► docs/design-review.md
        │
        ├─[L2]─► Impl Planner Agent ──► docs/impl-plan.md
        │
        ├─[L2]─► Implementation Agent ──► src/ + tests/
        │
        ├─[L2]─► Doc Sync Agent ──► docs/ (updated)
        │
        ├─[L2]─► Code Review Agent ──► output/reports/
        │
        ├─[L2]─► Verification Agent ──► output/test-results/
        │
        └─[L3]─► PR Agent ──► GitHub Pull Request

        All agents report back to orchestrator
```

### Phase 4 — Orchestrator Agent

**Goal**: Create the orchestrator — the single entry point that drives the full pipeline.

### Orchestrator responsibilities

* Read user story file passed as argument
* Coordinate each specialist agent in sequence using the **Copilot agent/handoff mechanism**
* Apply interaction level rules (L1/L2/L3) per agent
* Gate each step: check output file exists and is non-empty before proceeding
* Append run log to `docs/changelog.md` after each step
* Surface errors clearly if a gate fails

### Tasks

* [ ] `.github/agents/orchestrator.agent.md` — full controller logic with all 9 steps, gating, and interaction levels

**Deliverable**: Orchestrator Copilot Custom Agent committed.

---

### Phase 5 — Hooks

**Goal**: Configure **GitHub Copilot hooks** for logging and quality gates.

Hooks to configure:

* [ ] Pre-agent/tool execution → log which agent is being invoked to `docs/changelog.md`

**Deliverable**: Copilot hooks configuration with hooks configured and committed.

## Success Criteria

* [ ] Single invocation (`@orchestrator process user-stories/user-story-1.md`) drives the entire pipeline
* [ ] Requirements and Architecture agents ask clarifying questions interactively
* [ ] All other agents run autonomously and wait for human approval before proceeding
* [ ] PR is only created after explicit user confirmation
* [ ] All `docs/*.md` artifacts are populated and human-readable
* [ ] Generated Python code passes tests
* [ ] No subagent is ever invoked directly by the user

---

## Notes

* All agents are `.github/agents/*.agent.md` files and are implemented as **GitHub Copilot Custom Agents**
* Reusable agent capabilities are provided through `.github/skills/`
* Project-wide behavior is defined in `.github/copilot-instructions.md`
* Reusable workflows can be defined through `.github/prompts/`
* Hooks are configured through the Copilot hooks configuration
* No external SDK or API keys are required beyond the GitHub Copilot/GitHub environment already being used
* Pipeline is stateless per run — re-running regenerates all artifacts
* The pipeline is general-purpose: works for any Python project user story
